# 性能审计与优化备忘（代码级）

> 审计范围：全程序化 UI（`WarCouncilScreen.ts` ~2800 行）、资源管线（`assets/resources/`）与回合核心。
> 结论先行：**渲染层的主要成本是"无图集批处理的独立贴图节点"，逻辑层的主要成本是"整页重建"**。
> 两者在当前规模（设计分辨率 844×390、单场景、静态 UI）均可接受；上真机前按下文清单实测。

## 1. 快照数据（本仓库静态审计）

| 指标 | 数值 | 说明 |
| --- | --- | --- |
| UI 元素创建调用 | ~246 处 | `panel/rect/label/image`（每次页面重建都会重建其中的动态部分） |
| `repeatForever` 常驻补间 | 14 条 | 云影漂移 ×4、传令钮脉动、选中光圈、军议光晕、战报托举、护送/敌军标记、横幅摆动 |
| 每帧逻辑 | 近零 | `update()` 只在长按传令时工作，其余早退 |
| 资源体积 | ~17MB | 战图 + 31 张立绘（共 ~134KB）+ 字体子集 750KB + BGM 2.5MB + 8 个 SFX |
| 字体标签 | 数百个/页 | 全部 SHRINK 溢出 + 自定义字体 |

## 2. 已做的微优化

- **labelRegistry 泄漏修复**：字体加载完成前才登记标签；之后创建的标签直接挂字体，
  注册表不再随页面重建无限增长（此前只在字体应用时过滤一次死引用）。
- 云影/光圈等补间挂在会被 `setWorldStageVisible(false)` 隐藏的节点上——隐藏后不产生渲染开销。

## 3. 已评估、明确不做的"优化"

- **Label.cacheMode（BITMAP/CHAR）**：BITMAP 会为每个标签生成一张缓存纹理——数百标签
  = 数百张小纹理，内存换 CPU 反而亏损；CHAR 缓存只对重复单字符（如数字列）有利，
  收益不足以补偿复杂度。维持系统字体/自定义字体直绘。
- **停掉常驻补间**：全部是 transform/opacity 层级动画，无 Graphics 重绘；视觉生命感
  是核心体验，真机实测确认开销后再考虑降频。

## 4. 已知的结构性成本（真机若不达标，按此顺序处理）

1. **Draw Call 无批处理**：每个 `panel/rect` 是独立 Graphics 底图、每个 `image` 独立贴图，
   相邻同图不换纹理时 Cocos 才会合批；当前散贴图多，实测 Draw Call 可能上百。
   首选解法：**把图标/立绘/面板皮肤收进 SpriteAtlas**（Creator 自动图集，
   `assets/resources` 下新建 AutoAtlas 目录即可），UI 代码零改动。
2. **整页重建**：`renderPageAgain` = `removeAllChildren` + 全量重建（含事件绑定）。
   GC 压力集中在"点按页面"瞬间，不在帧间。若低端机点按掉帧：
   只重建变化的行（diff 更新），或对静态卡片做节点池。
3. **Graphics 圆角矩形**：每个面板独立 fill；可合并为"面板皮肤"图集后以 Sprite 绘制
   （`loadPanelSkins` 已为此铺路）。

## 5. 真机实测清单（上架前一次）

- [ ] Cocos 构建面板开启 profiler（`cc.debug.isRender` 或自定义帧率显示），
      记录：主城页 / 城池页 / 图鉴页 / 军议结算动画时的 FPS 与 Draw Call。
- [ ] 低端机（Android 8, 2GB RAM 档）连续 30 回合：有无发热降频、加载立绘时卡顿。
- [ ] 页面往返开关 50 次：内存是否平稳（验证 labelRegistry 修复与节点释放）。
- [ ] BGM 循环点听感（30s 无缝设计）+ 长按传令时音频是否卡顿。
- [ ] 云影漂移遮挡下触控命中不受影响（`TOUCH_START/END` 空函数已挡输入穿透）。
